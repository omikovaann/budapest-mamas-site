## 1. Компоненты и где что живёт

| Компонент | Где | Роль |
|---|---|---|
| Сайт | `website/` → Netlify (budapest-mamas.netlify.app) | Публичный гайд, 7 HTML-страниц, часть контента под кодом доступа |
| Netlify Function | `website/netlify/functions/check-code.js` | Серверная проверка кода доступа (см. §4) |
| SheetDB | Google-таблица через API | Хранит выданные коды, статус, счётчик активаций |
| Обработка чата | `telegram-bot/` | Категоризирует вручную экспортированные сообщения чата, предлагает правки в гайд (см. §6) |
| NotebookLM | облачный Google-продукт, доступен через Claude Code (MCP) | База знаний всей истории чата — контекст для анализа |
| Приватный GitHub | `github.com/omikovaann/budapest-mamas` | Полный проект (бот, приватные черновики, бизнес-стратегия), клон для Claude Code |
| Публичный GitHub | `github.com/omikovaann/budapest-mamas-site` | Только `website/` + `docs/` — чтобы Claude.ai мог читать код сайта через raw.githubusercontent.com |

## 2. Три инструмента, которые не синхронизированы автоматически

- **Claude.ai** (веб/телефон) — не видит компьютер пользователя и не видит NotebookLM напрямую.
  Между чатами помнит факты через собственную memory, но не файлы. Внутри одного чата помнит
  всё безусловно. Читает актуальный код сайта через `raw.githubusercontent.com/omikovaann/budapest-mamas-site/master/...`
  (публичный репозиторий, см. §1) — этот домен у Claude.ai всегда открыт без ограничений поиска.
- **Claude Code** (локально, `C:\Users\styl\Desktop\Guide`) — полный доступ к файлам и интернету,
  подключён к NotebookLM через MCP. Не видит memory Claude.ai — отдельная система.
- **NotebookLM** — отдельный продукт Google, доступен только через Claude Code.

GitHub — мост между ними: Claude Code пушит в приватный репозиторий как обычно через git;
публичный репозиторий — зеркало только кода сайта специально для чтения Claude.ai.

**Netlify подключён к GitHub напрямую** (с 2026-09-10): следит за веткой `main` приватного
репозитория (base directory `website`), деплоит сам при каждом `git push`. Ручная команда
`netlify deploy --prod --dir .` больше не нужна, но остаётся рабочей на случай форс-мажора
(Netlify CLI установлен и залогинен). Важно: GitHub App у Netlify должен иметь доступ к
приватному репозиторию `budapest-mamas` (не только к `budapest-mamas-site`) —
проверяется в github.com/settings/installations → Netlify → Configure.

## 3. Git-гигиена: что не коммитим и почему

В `.gitignore` явно исключены (и должны оставаться исключены):

- `archive/` — экспорт Telegram-чата: 44 файла чужих книг (авторское право) + сами сообщения
  и фото участниц чата (личные данные третьих лиц, не для версионирования)
- `notebooklm-data/exports/`, `telegram-bot/data/{raw,categorized,notebooklm}/` — то же самое
  в других форматах (дубли для загрузки в NotebookLM)
- `telegram-bot/config.py`, `.env` — токены и ключи

История до 2026-09-10 содержала всё это (чат когда-то закоммитили целиком). Локально она
сохранена на ветке `main-archive-backup` (никуда не пушится). Текущий `main` — чистая
история с одного коммита, без этих данных. **Не делать `git add -A` бездумно** — легко
случайно вернуть архив в индекс.

## 4. Монетизация и пейволл

- **Цена:** 3 500 HUF (~9 €), разово — доступ навсегда + обновления до конца 2026
- **Процесс продажи:** покупатель пишет `@omikova` в Telegram → платит через Revolut
  (0% комиссии) → получает именной код
- **Статус:** 5 покупателей, без публичного анонса — пришли сами через чат/сарафан
- **Технически:** каждый покупатель — отдельный код (не общий пароль). Код хранится в
  Google-таблице, проверка идёт через SheetDB API.
  - **До 2026-09-10** ссылка на SheetDB была захардкожена в клиентском `script.js` —
    значит, публично читаема, а незащищённый эндпоинт отдавал вообще все коды одним GET-запросом
    без авторизации. Уязвимость закрыта: проверка кода перенесена в серверную Netlify
    Function (`check-code.js`), `SHEETDB_API_URL` теперь только в переменной окружения
    Netlify, в браузер не попадает. Скомпрометированное подключение SheetDB отключено,
    создано новое.
- **Блокировка контента — только визуальная**, не серверная: платные блоки обёрнуты в
  `<div class="premium-wrap">`, при отсутствии доступа JS вешает класс `.locked`, который
  через CSS блюрит текст (`filter: blur`) и гасит клики. Сам текст физически лежит в HTML
  каждому посетителю — «Просмотр кода страницы» показывает всё без пароля. Это осознанный
  компромисс (не пересматривался в эту сессию), не путать с «контент реально защищён».

## 5. Free / paid структура по страницам

Паттерн одинаковый везде: вводная часть — бесплатно, конкретика (цены, контакты,
пошаговые инструкции) — платно.

| Страница | Бесплатно | Платно |
|---|---|---|
| `index.html` (Беременность) | С чего начать, таблица сравнения клиник | Разбор клиник, доула/акушерка/переводчик |
| `screenings.html` | Почти всё — что и когда делать, все анализы/НИПТ/ГТТ | Только «Клиники для скринингов» |
| `birth.html` (Роды) | Только «Где рожать» | Контракт, цены, эпидуралка, КС, послеродовой период |
| `documents.html` | «Какой у вас кейс» + начало Кейса 1 | Остальное по обоим кейсам |
| `baby.html` (Ребёнок) | Педиатр, Védőnő, TAJ, календарь прививок, **и весь блок «Скорая и неотложка» / «Детские больницы» / «Ребёнок заболел: алгоритм»** (сделано бесплатным 2026-09-10 по этическим соображениям — неотложная информация не должна быть за пейволлом) | Специалисты, УЗИ, аптечка, ГВ, прикорм, досуг, покупки, транспорт, поддержка мамы |
| `benefits.html` (Пособия) | Как устроена система, кому положены | CSED/GYED/GYES, pótlék, как оформить |
| `sadiki.html` (Сады/школы) | Ясли vs сад, гос vs частный | Конкретные сады с ценами, запись, школы, няни |

**Известный дисбаланс** (зафиксировано, не исправлено): `screenings.html` почти целиком
бесплатен, `birth.html`/`benefits.html`/`sadiki.html` — почти целиком платные. Решение,
трогать ли это, ещё не принято.

## 6. Пайплайн обновления гайда из чата

**2026-09-10: бота убрали из группового чата** — живой автосбор сообщений (бывший
`agent.py`, ходил в Telegram Bot API через `getUpdates`) больше не работает и удалён.
Токен бота при этом рабочий — личные сообщения боту (апрув от админа, см. шаг 4) всё ещё
доходят, это отдельный канал от группового чата.

1. Сбор теперь ручной: Telegram Desktop → Export chat history → формат **JSON** →
   `telegram-bot/import_export.py путь/к/result.json`. Дедупликация по id сообщения —
   можно экспортировать с перекрытием по датам, повторно обработанное не задвоится.
2. Категоризация — тот же батч-вызов Claude Haiku (`classify_messages_batch`, теперь в
   `import_export.py`), понимает контекст/синонимы/опечатки; при сбое API — фолбэк на
   старый keyword-метод. Не зависит от способа сбора — код не менялся.
3. `analyze.py` — Claude предлагает правки по каждой категории отдельно (одна упавшая
   категория не роняет весь прогон)
4. Человек утверждает
5. `apply.py` — применяет правки к нужной странице гайда (не всегда `index.html` — раньше
   был баг), проверяет `tags_balanced()` (не даёт закоммитить битую разметку с несовпавшими
   `<div>`/`<section>`), репортит в Telegram какие конкретно правки не применились
6. Git commit → `git push` → Netlify деплоит сам (автодеплой, см. §2)
